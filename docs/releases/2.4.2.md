# Bazis 2.4.2

## Fixes

- **`get_fields_info()` listed a relation named `None`** for a symmetrical many-to-many
  relation of a model to itself (such as `transits_related` of bazis-statusy): it has no
  reverse accessor. `manage.py bazis_introspect` then failed with
  `TypeError: '<' not supported between instances of 'NoneType' and 'str'`, so bazis-mcp
  showed no facts of a project with bazis-statusy.
- **Translated fields with fixed languages** (bazis-permit 2.4.1, bazis-statusy 2.4.1) in a
  language they have no column for: the calculated fields (`FieldJson` and others) selected
  a column that does not exist (`FieldError`), and the getter of a `TranslatedField` raised
  `AttributeError`. Now they use the base language (`en` of `en-us`) or the first language
  of the field: new `bazis.core.utils.orm.translated_column(name, field)`.

## Development

- The Integration workflow installs the Bazis packages from their checkouts also when a
  change raises the minimal version of a package to the one it is about to release
  (`scripts/integration_install.sh` overrides the requirements on them).

Found by the evals of bazis-cli.
