# Bazis 2.6.1

## Fixes

- **The translations no longer depend on the process.** The core built `LOCALE_PATHS` from
  a set of module names, so when two packages translate the same msgid differently (for
  example `"Name"`: "Название" in bazis-permit, "Наименование" in bazis-statusy and
  bazis-uploadable), the winner changed with the hash seed of the process: the titles in
  the OpenAPI, and the hash of a frontend contract generated from it, changed between
  processes. `LOCALE_PATHS` now follows the order Django gives the catalogs of the apps:
  the `locale` of the project, then the installed apps in the order of `INSTALLED_APPS`,
  then the other Bazis packages (used without being installed) by name. A package that is
  not installed no longer outranks an installed one, and the global catalog of Django is
  no longer in `LOCALE_PATHS` (Django loads it itself, under all the others). A project
  that relied on a translation winning by chance gets the one of its first installed app;
  translate the msgid in the project's `locale` to choose another.
- **The `filter:` restrictions of a field (bazis-permit) are sorted**, so the name of a
  schema patched with them no longer depends on the process either.
