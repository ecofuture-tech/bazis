# Bazis 2.6.1

## Fixes

- **The translations no longer depend on the process.** The core built `LOCALE_PATHS` from
  a set of the modules imported before the settings plus the Bazis packages, so when two
  packages translate the same msgid differently (for example `"Name"`: "Название" in
  bazis-permit, "Наименование" in bazis-statusy and bazis-uploadable), the winner changed
  with the hash seed of the process and with what the process had imported (manage.py,
  uvicorn and pytest differ): the titles in the OpenAPI, and the hash of a frontend
  contract generated from it, changed between processes. The apps of the project, not yet
  imported then, were missing, so a Bazis package that is not installed outranked them.
  `LOCALE_PATHS` now depends only on the settings and follows the order Django gives the
  catalogs of the apps: the `locale` of the project, then the installed apps in the order
  of `INSTALLED_APPS` (found without importing them), then the Bazis packages that are not
  installed (their abstract models are used) by name. Libraries that are not apps and the
  global catalog of Django are no longer in `LOCALE_PATHS` (Django loads the latter
  itself, under all the others). A project that relied on a translation winning by chance
  gets the one of its first installed app; translate the msgid in the project's `locale`
  to choose another.
- **The `filter:` restrictions of a field (bazis-permit) are sorted**, so the name of a
  schema patched with them no longer depends on the process either.
