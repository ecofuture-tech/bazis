# Bazis 2.8.1

## Fixes

- **The names of the models made by `AbstractForeignKey` no longer depend on the
  language.** `AbstractForeignKey` makes a model for each model of its target (the history
  of the statuses of bazis-statusy, `<Model>StatusyTransit`), and its `verbose_name` and
  `verbose_name_plural` were composed with an f-string when the model was made, at import,
  in the language active then: in a project with `LANGUAGE_CODE` `ru` the migrations had
  Russian names (`'Booking. Факт перехода'`), and they changed with the translations and
  the catalogs installed. The names are lazy now (`format_lazy`): `makemigrations` writes
  the English msgids (`'Booking. Transit fact'`) whatever the language, and the admin and
  the schemas show them in the active language. A project whose migrations have the
  translated names gets one `AlterModelOptions` migration with the English ones; it
  changes no table.
- **The relationships endpoints answered 500 on a read-only relation.** A relation that
  the route makes read-only in its update schema (`SchemaField(read_only=True)`, the field
  permission `readonly` of bazis-permit) stays in the schema, and its value is dropped
  when the data is validated; `relationships_validate` only checked that the relation is
  in the schema, so `PATCH`, `POST` and `DELETE` on `/{item_id}/relationships/<field>`
  failed with a `KeyError`. They answer 403 `ERR_RELATIONSHIP_READONLY` (source parameter
  `/related_field_name`), as for a relation that is not in the update schema. An update
  of the item still ignores a read-only relation, as it ignores a read-only attribute.
