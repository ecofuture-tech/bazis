# Bazis 2.3.1

## Security

- **The relationships endpoints changed any relation of any object.**
  `POST/PATCH/DELETE /{id}/relationships/{name}` loaded the object directly from the model
  and changed the relation named in the URL, without the checks of an update: the route
  queryset, the update schema of the route (which relations are exposed and writable),
  the `filter:` restrictions of the fields, and the checks of permission routes. For
  example, any authenticated user could add himself to Django groups with all permissions
  (`/users/user/<id>/relationships/groups`), and in projects with bazis-permit assign
  himself any role or change objects he cannot change.

  The endpoints now take the object through the route and accept only the relations of
  the update schema of the route (for the current user); other names fail with 403 and
  `ERR_RELATIONSHIP_READONLY`. The `filter:` restrictions apply to added and set objects,
  and the change runs in a transaction between the new hooks
  `hook_before_relationships_change` and `hook_after_relationships_change`, which
  bazis-permit 2.3 uses for its checks. Unknown relation names fail with 403 instead
  of 500.

  A project that changed relations through these endpoints which its routes do not expose
  must add them to the update schema of the route (`fields` for `CrudApiAction.UPDATE`).

## Fixes

- `readonly_validator` was marked as deprecated while the schema builders use it, which
  emitted a `DeprecationWarning` on every validated request.
- An invalid escape sequence in a docstring emitted a `SyntaxWarning` on import.
