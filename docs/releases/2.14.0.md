# Bazis 2.14.0

## Changes

- **Lazy texts in the models of custom routes no longer break the OpenAPI.** A request or
  response model of a project with `Field(title=_('…'))` (or a lazy `description`), a
  parameter with `Query(description=_('…'))` or an operation with a lazy `summary` made
  `app.openapi()` (and `/openapi.json`, the contract export of bazis-front) fail with a
  `ValidationError` of FastAPI: it copies these texts into the document as they are and
  refuses a lazy text where it expects a string. The core now writes every lazy text of
  the document in the active language when it is generated (`TranslatedOpenAPI` of
  `bazis.core.utils.fastapi_monkey_patch`), so the OpenAPI, built once per language,
  follows the language of the request as the schemas of the core do. Keep the texts lazy.
- **`TranslatedJsonSchema` and `TranslatedSchemaModel`** (`bazis.core.utils.schemas`): a
  JSON schema generator that writes the lazy texts of the models (titles, descriptions,
  `json_schema_extra`: labels, examples) in the active language at each generation, and a
  base model whose `model_json_schema()` uses it unless another `schema_generator` is
  passed, for a JSON schema the code reads itself outside the OpenAPI. They replace the
  classes of the same name of bazis-statusy (2.11 uses the ones of the core).
  `bazis.core.utils.schemas.translated(value)` is the conversion they share.

## Notes

- Lazy examples go in `json_schema_extra={'examples': [_('…')]}`: pydantic serializes
  `Field(examples=...)` when it defines the model and refuses a lazy text there.
