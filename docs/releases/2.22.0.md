# Bazis 2.22.0

## Added

- **Labels of the Django choices in the JSON schemas of `TranslatedJsonSchema`.** Bazis 2.21
  added `enumDict` (value to `str(label)` in the language of the generation) to the schema of
  a type that is a subclass of `TextChoices` / `IntegerChoices` in the OpenAPI only. A JSON
  schema the code reads itself, `TranslatedSchemaModel.model_json_schema()` or a model with
  `schema_generator=TranslatedJsonSchema` (the payload type of a transit of bazis-statusy: the
  body of a transit in the transits of an item and the payload of the capabilities in the
  contract of bazis-front), now has the same labels: the dialog of a transit shows "Client
  changed their mind", not `changed_mind`. Both generators take them from one mixin,
  `ChoicesJsonSchemaMixin` (`bazis.core.utils.schemas`). As in the OpenAPI, a `Literal` and
  an `Enum` that is not a Django `Choices` get none, and the `__empty__` variant of the
  choices is not a variant.

- **A limit of the size of a request body: `BAZIS_API_MAX_BODY_SIZE`** (bytes,
  `BS_BAZIS_API_MAX_BODY_SIZE`, `0` - no limit, the default; not dynamic). A larger request
  is refused with 413 `ERR_BODY_TOO_LARGE` in the JSON:API format of the other errors
  (`JsonApiBodyTooLargeException`, translated, with the headers of CORS): by its
  `Content-Length` before the application runs, and a body sent without one (chunked) as
  soon as the bytes received exceed the limit, so that no route reads or parses (JSON,
  multipart) a larger body. A middleware of the application applies it to every HTTP route,
  also the plain FastAPI routes of the packages.

## Upgrading

Nothing is required in the code. The JSON schemas of `TranslatedJsonSchema` gain `enumDict`
for the types of the choices, so the schemas of the transits of bazis-statusy whose payload
has such a field change: generate the contract of bazis-front again (`bazis-front update`,
`screens`), whose payload schemas of the transits gain the labels.

The limit of the body is off until it is set. Set it in production above the largest request
the project accepts (with bazis-uploadable at least `BAZIS_FILE_UPLOAD_MAX_SIZE` plus the
multipart overhead), and keep the limit of the reverse proxy (`client_max_body_size` of
nginx): the proxy refuses a large body before it reaches the application at all.
`DATA_UPLOAD_MAX_MEMORY_SIZE` is the setting of Django, for the admin; the API routes do not
use it.
