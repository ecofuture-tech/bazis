# Bazis 2.2.9

Settings keep the original `django.conf` module and settings object. Early imports,
the Bazis accessor, and Django `override_settings` now share the same state.
Nested overrides restore their previous values without persisting them to Constance.
Only the application's settings singleton receives dynamic-setting behavior; separate
`LazySettings` instances remain independent.

Dynamic settings use typed defaults during Django app initialization and Constance
after startup. Database failures after startup propagate instead of returning an empty
string. Deployments must provide a migrated, reachable Constance database.

Pagination reads its configured maximum on each request. Exceeding it still returns
HTTP 422, preserving the previous validation contract.

Regression coverage includes settings identity, nested overrides, restoration,
Constance persistence, startup defaults, database failure, independent settings
instances, and pagination validation after a configuration change. The OpenAPI test
constructs its app under its own DEBUG setting instead of depending on test order.

Known existing failure: `tests/test_sparse_fieldsets.py::test_sparse_fieldsets` returns
HTTP 422 for a related-field projection. The identical failure was reproduced with
the published 2.2.8 wheel using the same sample and test environment. This release
does not change sparse-fieldset generation.
