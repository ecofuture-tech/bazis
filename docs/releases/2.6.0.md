# Bazis 2.6.0

## Features

- **The OpenAPI schema documents the errors of the core routes.** The operations of an
  item (`{item_id}` in the path: retrieve, update, delete, the relationships routes,
  `schema_retrieve`, `schema_update`, `dict_data`) document the 404 response and the
  relationships routes the 403 response (read-only relationship, restricted objects), both
  with the schema `SchemaErrors` (the JSON:API errors), so a client generator types them.
  The schema names, the `operationId` and the existing responses do not change, and the
  schema is still deterministic. The core has no authentication, so it documents no 401
  and no `security`: bazis-users declares them for its routes.
- **`InitialRouteBase.route_responses(route_ctx)`**, the extension point of a route class
  or a package that fails its routes with a status: extend the result of `super()` to add
  the response to the OpenAPI operations. The `responses` of a decorator take priority.
- **`InitialRouteBase.route_openapi_extra(route_ctx)`**, the same for the facts of an
  operation: it returns the `x-bazis` extension, a route class or a package extends it (for
  example with `security`), and `endpoint_register` merges it, key by key and on a copy,
  under the `openapi_extra` the route declares itself. The route context is not changed,
  so the result never depends on the order the route classes were registered in. As a
  consequence an `x-bazis` the route declares itself now wins over the generated one.
