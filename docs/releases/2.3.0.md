# Bazis 2.3.0

Dependencies are updated to the current releases and verified on Python 3.12, 3.13
and 3.14: Django 6.1, FastAPI 0.142, Starlette 1.x (0.48 or newer), Pydantic 2.13,
pydantic-settings 2.15, django-redis 7, django-sequences 3, django-pghistory 3.9,
django-pgtrigger 4.17 and aiohttp 3.14 (3.9 had known vulnerabilities and no wheels
for recent Python versions). The unused direct `anyio` pin is removed; it is still
installed through Starlette. Unpinned dependencies received minimum versions.

Since FastAPI 0.137, `include_router` no longer copies routes: the parent router keeps
a reference to the included router and builds the effective routes lazily. Bazis adapts
to this model:

- `BazisRoute` no longer carries a copy of `APIRoute.__init__` and does not import
  private FastAPI helpers (`get_body_field`, `get_flat_dependant` and others were
  removed in FastAPI 0.141). FastAPI does not clone the response field anymore, which
  was the reason for the copy.
- `BazisDummyRoute` stores only the route declaration, including the new
  `strict_content_type` and `stream_item_type` attributes; FastAPI builds the working
  route from it when the router is included into the application.
- `BazisRouter.routes_cast` and the new `bazis.core.routing.iter_api_routes` walk
  included routers recursively without building them.
- The effective routes are built during application initialization, so the schema
  generation cost is not paid by the first request and declaration errors surface
  at startup.
- `schemas_build_lang` no longer includes the project router a second time.

The generated OpenAPI schemas are identical to the previous release.

Other changes:

- A retrieve request with both sparse fieldsets and `include` no longer fails with
  HTTP 422: the response schema used the request resource schema with required fields.
  This fixes the known failure of `test_sparse_fieldsets` noted in 2.2.9.
- The `BaseModel.model_dump` patch wraps the original method and accepts all its
  arguments (`context`, `serialize_as_any`, `exclude_computed_fields`, ...).
- The patch of `pydantic._internal._generate_schema.add_json_schema_extra` is removed:
  the function does not exist in supported Pydantic versions, so the patch had no effect.
- `HTTP_422_UNPROCESSABLE_CONTENT` replaces the deprecated Starlette constant, and
  `model_fields` is read from the schema class instead of the instance.
- SQL assertions in tests no longer depend on the PostgreSQL version (Django emits
  `JSON_OBJECT` on PostgreSQL 16+) or on the Django version (6.1 quotes subquery aliases).

## Breaking changes

- **Email settings are renamed.** Django 6.1 deprecates `EMAIL_*` in favour of `MAILERS`
  (removal in Django 7.0), and Django does not allow combining them. The Bazis settings
  are now `BAZIS_EMAIL_BACKEND`, `BAZIS_EMAIL_HOST`, `BAZIS_EMAIL_PORT`,
  `BAZIS_EMAIL_HOST_USER`, `BAZIS_EMAIL_HOST_PASSWORD`, `BAZIS_EMAIL_USE_TLS` and
  `BAZIS_EMAIL_USE_SSL`; `MAILERS['default']` uses `bazis.core.mail.DynamicSMTPEmailBackend`,
  which reads them at runtime, so they stay editable in the admin panel.
  The former `BS_EMAIL_*` variables are still read with a deprecation warning, and the
  migration `core.0003_rename_email_settings` moves the stored values to the new keys.
  Code that reads `settings.EMAIL_HOST` and the like must use the new names
  (the old ones raise `AttributeError` while `MAILERS` is configured).
- **`SECRET_KEY` is required.** It is no longer generated per process: with
  `DEBUG=false` an absent key, a key shorter than 32 characters, with fewer than 5 unique
  characters or a `django-insecure-` key stops the application with `ImproperlyConfigured`.
  With `DEBUG=true` a warning is logged and an absent key is replaced by a temporary one.
- **Redis is required as the default cache.** The default cache backend is now
  `django_redis.cache.RedisCache` (`redis://127.0.0.1:6379/0`); the system check
  `bazis.E001` reports a backend without `delete_pattern`.
- `pytz`, `python-jose` and `dateparser` are no longer dependencies (the core does not use
  them); packages that need them must declare them. Time zone choices use `zoneinfo`.

## Fixes and improvements

- Errors raised by routing itself (404 for an unknown path, 405 for a wrong method) are
  returned in the JSON:API format; the headers of HTTP exceptions (e.g. `Allow`,
  `WWW-Authenticate`) are set on the response, and their `code` is included.
- A malformed filter returns 400 with the `ERR_FILTER` code instead of 500.
- Sorting adds the primary key as the last criterion: with non-unique sorted values the
  order was undefined, so pagination could skip or repeat items between pages.
- Generated schemas are evicted from the cache after `BAZIS_SCHEMA_CACHE_TTL` seconds
  without use (3600 by default, 0 disables eviction) and removed from the module they
  were registered in, so they can be garbage collected.
- `ALLOWED_HOSTS`: the default `*` is no longer appended to the hosts of the project
  settings module, which disabled host validation. Merged settings lists are deduplicated.
- The list of Bazis apps in `BS_BAZIS_APPS` / `BS_BAZIS_CONFIG_APPS` is parsed as JSON or
  a Python literal instead of `eval`.
- The model item cache keys include the app label (models with the same name in different
  apps shared entries), and deleting an item invalidates the cache as saving does.
- Migration `core.0002` no longer prints the converted values, which could include secrets.
- The sample project no longer imports from `tests` and runs without extra `PYTHONPATH`.
- A GitHub Actions workflow runs the linter and the tests on Python 3.12, 3.13, 3.14 and
  with the lowest allowed dependency versions, against PostGIS and Redis.
