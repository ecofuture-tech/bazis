# Bazis 2.3.0

Dependencies are updated to the current releases and verified on Python 3.12, 3.13
and 3.14: Django 6.1, FastAPI 0.142, Starlette 1.x (0.48 or newer), Pydantic 2.13,
pydantic-settings 2.15, django-redis 7, django-sequences 3, django-pghistory 3.9,
django-pgtrigger 4.17 and aiohttp 3.14 (3.9 had known vulnerabilities and no wheels
for recent Python versions). The unused direct `anyio` pin is removed; it is still
installed through Starlette. Unpinned dependencies received minimum versions.

Since FastAPI 0.137, `include_router` no longer copies routes: the parent router keeps
a reference to the included router and builds the effective routes lazily. Bazis adapts
to this model:

- `BazisRoute` no longer carries a copy of `APIRoute.__init__` and does not import
  private FastAPI helpers (`get_body_field`, `get_flat_dependant` and others were
  removed in FastAPI 0.141). FastAPI does not clone the response field anymore, which
  was the reason for the copy.
- `BazisDummyRoute` stores only the route declaration, including the new
  `strict_content_type` and `stream_item_type` attributes; FastAPI builds the working
  route from it when the router is included into the application.
- `BazisRouter.routes_cast` and the new `bazis.core.routing.iter_api_routes` walk
  included routers recursively without building them.
- The effective routes are built during application initialization, so the schema
  generation cost is not paid by the first request and declaration errors surface
  at startup.
- `schemas_build_lang` no longer includes the project router a second time.

The generated OpenAPI schemas are identical to the previous release.

Other changes:

- A retrieve request with both sparse fieldsets and `include` no longer fails with
  HTTP 422: the response schema used the request resource schema with required fields.
  This fixes the known failure of `test_sparse_fieldsets` noted in 2.2.9.
- The `BaseModel.model_dump` patch wraps the original method and accepts all its
  arguments (`context`, `serialize_as_any`, `exclude_computed_fields`, ...).
- The patch of `pydantic._internal._generate_schema.add_json_schema_extra` is removed:
  the function does not exist in supported Pydantic versions, so the patch had no effect.
- `HTTP_422_UNPROCESSABLE_CONTENT` replaces the deprecated Starlette constant, and
  `model_fields` is read from the schema class instead of the instance.
- SQL assertions in tests no longer depend on the PostgreSQL version (Django emits
  `JSON_OBJECT` on PostgreSQL 16+) or on the Django version (6.1 quotes subquery aliases).

Known deprecation: Django 6.1 deprecates the `EMAIL_*` settings in favor of `MAILERS`
(removal in Django 7.0). Bazis still defines them as dynamic (Constance) settings, and
Django forbids combining them with `MAILERS`, so the migration requires renaming the
settings and is left for a separate release.
