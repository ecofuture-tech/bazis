# Bazis 2.13.0

## Changes

- **`manage.py bazis_doctor` runs the database checks.** The checks tagged `database`
  (Django runs them only for the databases it is given) compare the project with the data
  of its database, such as the roles and workflows declared in `roles.py` / `workflow.py`
  against the rows (`permit.W005`/`W006`, `statusy.W003`/`W004`/`E004` of bazis-permit and
  bazis-statusy 2.9.0). The doctor passed no database, so it never showed them; only
  `manage.py check --database default` did. It now runs them against the database
  `default` when it can be reached, and skips them with the info `bazis.database` (naming
  the connection error) when it cannot, as before the database is created: the doctor does
  not fail then. The new option `--database ALIAS` (repeatable, as in `check`) names the
  databases; one that cannot be reached is the error `bazis.database`. `bazis.database`
  is a system check message: `SILENCED_SYSTEM_CHECKS` silences it. A PostgreSQL database
  is probed by a connection of its own with a connect timeout of at most 5 seconds (the
  connections of the project are not changed), so an unreachable host does not hang the
  doctor. With the databases, the checks of the models that depend on a database (long
  column names, indexes, constraints, the checks of the fields by the backend) get those
  aliases, as with `migrate` and `check --database`. bazis-mcp (`run_doctor`) runs
  `bazis_doctor --json` and reports these messages too.
- `bazis.core.introspect.check_messages(deploy, databases=())`: the aliases to run the
  database checks against; `introspect.message_dicts(messages)` gives check messages as
  the dictionaries of `check_messages`, without the silenced ones.

## Upgrading

A project whose database is up now sees the warnings of its database checks in the doctor
(and in `run_doctor` of bazis-mcp); fix them (for the declarations: `manage.py migrate`) or
silence them as before. A CI that runs the doctor before `migrate` is not affected: the
checks of the declarations skip a database whose migrations are not all applied.
