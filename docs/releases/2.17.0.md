# Bazis 2.17.0

## Features

- **The aggregates of a list: `meta=aggregates`.** Every list of a `JsonapiRouteBase`
  computes the totals of its objects in one query when the request asks for the meta
  `aggregates` (a dashboard tile, a chart), with the query parameters
  `aggregate=<term>,...` and `group=<field>[:<bucket>]`:

  ```
  GET /api/v1/crm/order/?meta=aggregates&aggregate=count,sum(amount)&filter=paid=true
  "meta": {"aggregates": {"count": 4, "sum(amount)": "60.50"}}

  GET /api/v1/crm/order/?meta=aggregates&aggregate=sum(amount)&group=dt_created:month
  "meta": {"aggregates": [
      {"group": "2026-01-01", "values": {"sum(amount)": "30.50"}},
      {"group": "2026-02-01", "values": {"sum(amount)": "30.00"}}
  ]}
  ```

  - A term is `count` (the objects), or `sum`, `avg`, `min`, `max` or `count` of a field:
    `sum(amount)` (`count(f)` counts the objects with a value of `f`). Without `aggregate`
    the term is `count`. The key of a value is the term as written.
  - `group` is a field with `choices`, a boolean, a foreign key or a one-to-one field, or a
    date or a date-time field with a bucket: `:day`, `:week` (from Monday) or `:month`, in
    the time zone of the project. With it `meta.aggregates` is a list of
    `{"group", "values"}` ordered by the value, the objects without one last
    (`"group": null`). A group is a string: the choice, `true`/`false`, the id of the
    related object, the ISO date of the start of the bucket.
  - A request groups at most `BAZIS_API_AGGREGATE_GROUPS_MAX` groups (a new setting,
    `BS_BAZIS_API_AGGREGATE_GROUPS_MAX`, default 1000, not dynamic): more is 400
    `ERR_AGGREGATE` at `/query/group`, "More than 1000 groups of 'customer': narrow the
    list with a filter, or group by a date field by week or month". The totals without
    `group` are not limited.
  - The values follow the data of JSON:API: a decimal is a string, a date or a date-time
    ISO 8601; a count is an integer, the average of an integer field a float. Over no
    object `count` is 0 and the other terms `null`; the groups are `[]`.
  - The objects are those of the list with its `filter` and `search`
    (`get_queryset_for_list` of the route: bazis-permit restricts it to the objects the
    user may view), not its page, its sorting or its sparse fieldsets: an aggregate never
    counts an object the list would not show, and counts each once, by its key, also when
    a join of the list repeats it.
  - A field is a column of the model that the `filter` of the route reaches for the user
    (the LIST schema of the route, `query_fields`, which bazis-permit narrows to the
    fields the user sees in every object): an aggregate tells no more than the filter. A
    calculated field, a to-many relation and a path through a relation are not aggregated.
  - `sum` and `avg` take a number field, `min` and `max` a number or a date, `count` any
    field. Anything else (an unknown or a hidden field, a function that does not apply, a
    bucket of a field that is not a date, a date without a bucket) answers 400
    `ERR_AGGREGATE` with the pointer `/query/aggregate` or `/query/group`; a hidden field
    is answered as one that does not exist. Without `meta=aggregates` the parameters are
    not read and nothing is computed.

  The service is `bazis.core.services.aggregating.ServiceAggregating` (`apply(queryset)`,
  in the LIST injections as `inject.aggregating`); the response types are
  `AggregatesMeta` and `AggregatesGroup` of the same module. The OpenAPI of every list
  has the two parameters and `meta.aggregates`.

## Upgrading

- A route class or a package that defines its own attribute `aggregates`, or an injection
  `aggregating` in the LIST injections, overrides the new ones: rename it.
- A client generated from the OpenAPI gets the new query parameters and the meta; a
  client that does not ask for `meta=aggregates` sees no change.
