# Bazis 2.3.2

## Security

- **The relationships endpoints did not apply the `filter:` restrictions to the unlinked
  objects** (2.3.1 checked only the added and set ones). `DELETE /{id}/relationships/{name}`
  removed objects the user may not touch, `PATCH` unlinked the objects left out of the
  list, and `DELETE` of a to-one relation cleared a value the user could not change with an
  update. Every object an action links or unlinks must now match the restrictions;
  otherwise the request fails with 403. The objects a `PATCH` keeps are not checked.

## Changes

- Ids of missing objects in a relationships request fail with 403 (since 2.3.1).
- A response to a request with `include` is validated with the response schema of the
  resource for every action, not only for retrieve (since 2.3.0).
- `with_cache_openapi_schema` no longer stores the schemas it returns: the cache was never
  read and only held memory. `TTLCache` keeps only the methods the schema cache uses.

## Release

- The Release workflow refused a release after its pre-release (`2.4.0` after
  `2.4.0-rc1`): the versions are now compared with pre-releases before releases.
- The `test` extra requires bazis-test-utils 2.3.
