# Bazis 2.13.2

## Fixes

- **The connection of a thread is closed when the thread ends.** The sync endpoints (and
  the sync dependencies) run in the worker threads of AnyIO, each with its own database
  connection, which it keeps between the requests for `CONN_MAX_AGE` (60 s by default).
  AnyIO ends a worker after 10 s without work, before `CONN_MAX_AGE` is past, and the
  connection of the ended thread, which no thread can use any more, is in a reference
  cycle: it was closed only when the cyclic garbage collector freed it, with a
  `ResourceWarning` of psycopg, and its PostgreSQL session stayed open until then. Under a
  varying load the idle sessions piled up between the collections, in every process of
  the server, up to the connection limit of the database. The core now records the
  connections opened by the threads other than the main one (the `connection_created`
  signal) and closes them when their thread ends, whatever started the thread (AnyIO, the
  per-request thread of the Django ASGI handler, a thread of a package). A thread still
  reuses its connection while it lives, and the endpoint still closes the connection of
  its thread once it is past `CONN_MAX_AGE` or broken, as before.
- The ASGI middleware that called `close_old_connections` before and after every request
  is removed: it ran in an arbitrary worker thread, not the one of the request, so it
  rarely closed the connection it was meant for, and took two worker threads of the pool
  per request, also for the async routes and the files. The endpoint closes the
  connection of its own thread, and the connection of an idle worker is closed when the
  worker ends.

## Upgrading

Nothing to change. A project that worked around the idle sessions (`CONN_MAX_AGE=0`, a
periodic `gc.collect()`, closing the connections in its own middleware) can drop the
workaround. A test that counted the database sessions of a server can see fewer of them.
