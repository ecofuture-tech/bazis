# Bazis 2.19.1

## Fixed

- **A field with a callable source failed the schema with a `TypeError` (up to 2.19.0).**
  `SchemaField(source=<function>)` is documented as a field computed by
  `source(route_cls, item)`, and the builders of the schemas call it for the value and take
  the type from its return annotation; but the factory of the fields then looked the source
  up as an attribute of the model (`getattr(model, source)`, for a filter by a calculated
  property or a translated field) and raised
  `TypeError: attribute name must be string, not 'function'` while the schemas of the route
  were built. A callable source names no attribute of the model now: the field is read-only,
  can neither filter nor order, and shows the value of the function, also when it is named
  as a column of the model, which it replaces in the schema. bazis-bg 2.7 relies on it.

  The function must be of the module level: the names of the schemas are a hash of their
  fields, which takes the function by its qualified name, and a lambda or a nested function
  gives names that change between processes.
