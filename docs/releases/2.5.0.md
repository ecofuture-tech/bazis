# Bazis 2.5.0

## Changes

- **A filter lookup that Bazis does not support is an error 400 `ERR_FILTER`.** The lookup
  suffixes of `filter` are not Django lookups; an unknown one was ignored, so the condition
  silently became another one: `name__in=a,b` compared `name` with `'a,b'`, `name__icontains=x`
  and `price__in=1,2` were equality, `description__gt=x` a substring search, a range field
  without a suffix or with an unknown one gave no condition at all, `point__foo=...` a match
  within 10 m. Clients got a wrong (usually empty) list instead of an error. Now a field
  accepts only the documented suffixes (see `docs/openapi.rst`, "Supported Operations in
  Filters"), any other one is answered with 400 and the list of the supported ones;
  `QueryToOrm` raises `ValueError`. Array fields accept `overlap`, `contains`, `contained_by`
  (other Django array lookups such as `len` are refused); range fields
  `contains`, `contained_by`, `overlap`, `fully_lt`, `fully_gt`, `not_lt`, `not_gt`,
  `adjacent_to` (not the transforms `isempty`, `lower_inc`, ...).

## Fixes

- **`__isnull` works for every field that is not a relation**, as documented: a `TextField`
  searched for the word "true", an array field and a geo point failed, a range field gave no
  condition.

## Documentation

- The filter grammar in `docs/openapi.rst`, the README and `AGENTS.md` lists the supported
  suffixes per field kind and how the server decodes the expression (once more, then every
  value once more: a value with `&|()[]~=+%` is percent-encoded twice inside the expression).
