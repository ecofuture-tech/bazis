# Bazis 2.5.0

## Breaking changes

- **Filters reject what they do not understand** (`?filter=`, the permission selectors of
  bazis-permit and the `filter:` restrictions). An unknown field, an unknown name after a
  relation or a lookup the field does not support is a 400 `ERR_FILTER` error that lists
  the supported lookups. Before, such a filter silently built a different condition:
  `name__in=a,b` compared the name with `'a,b'`, `__icontains` and `__contains` compared
  for equality, `description__isnull=true` searched for the word "true", a range field
  without a lookup and an unknown field (`foo=1`) added no condition, and
  `child_entities__isnull=true` meant "has children". Now `isnull` works for every field
  that is not a relation, `rel__isnull` is the opposite of `rel__exists`, and `search` is
  accepted on string fields only. The supported lookups are listed in `bazis/core/AGENTS.md`
  and `docs/openapi.rst`. A permission or restriction string with an unknown field or
  lookup now fails the request instead of building a wrong condition; none of the Bazis
  packages has such a string.
- **The core declares `AUTH_USER_MODEL` and `AUTHENTICATION_BACKENDS`** with the defaults of
  Django, so `BS_AUTH_USER_MODEL` and `BS_AUTHENTICATION_BACKENDS` work in every project. A
  Bazis package declares only the settings it owns and never defaults a Django setting:
  bazis-users no longer makes `users.User` the user model of every project that merely has
  it installed (which made Django fail in projects without the users app). A project with
  bazis-users sets `BS_AUTH_USER_MODEL=users.User`; without it the user model is now
  `auth.User`, and bazis-users reports `users.E001`.

## Features

- **`x-bazis` in the OpenAPI schema.** Every operation of a route class carries
  `{"resource", "route_set", "action", "kind"}`, so client generators know the resource and
  the action of an operation without parsing `operationId`. `kind` is the new enum
  `RouteKind` (`collection`, `create`, `item`, `update`, `delete`, `relationship`, `schema`,
  `other`); the `http_*` decorators take `kind=`. `bazis_introspect` reads the same data
  and also reports the `kind` of each route.
- **New check `bazis.W002`**: `BS_BAZIS_APPS` or `BS_BAZIS_CONFIG_APPS` is an empty list,
  which turns off the settings of every Bazis package.

## Fixes

- **The OpenAPI schema is deterministic.** A field whose Django default is a callable
  (`auto_now`, `timezone.now`, `uuid4`, a database lookup such as the initial status of
  bazis-statusy) had the value computed when the schema was built as its `default`; such a
  default is now never evaluated and the field has no `default` in the schema. The `id`
  example of the models with `UuidMixin` is derived from the model label instead of being
  random.
- The docstring of `conf_modules` states the real priority of the settings modules.
